v2.3.2：修复“通知已提交，但通道已关闭震动”仍被记成成功派发的漏洞。标准模式明确记录 blocked_channel / blocked_notification，不凭广播送达或 API 返回宣称手机已震动。

新增“启用原生兼容震动并自检”。仅在用户主动选择后生效：普通任务的所有梯度、截止、课程与测试共用持久化原生路径，到点进入有限前台服务，再以通知用途请求震动；纯震动约 2.2 秒退出，有铃声保留原来的 4 秒。无后台轮询、不关闭电池优化、不申请省电白名单。系统静音、勿扰及全局震动策略仍然有效。

兼容模式使用独立的无声音、无通道震动通知通道，避免系统把无声音频再转成震动。用户若修改了兼容通道，派发时检查实际设置并选择单一来源。原有通知通道及用户偏好保留，缺省继续跟随系统通知。

自检调用真实原生震动接口；只报告设备能力、策略阻止或请求已提交，手机是否有实际触感由用户确认。诊断显示静音/勿扰、设备震动器、通知音量、震动强度、应用震动操作状态；从系统设置返回后自动只读刷新。修正设备型号及原型介绍文案。

系统横幅设置与自定义悬浮窗设置分别提供入口。应用内下载提示不算跨应用横幅；重要性 4 仅表示具备条件，不能证明 ColorOS 已弹出。签名不能自动解除未知来源悬浮窗限制，仍以手机实际提供的受限设置选项为准。

检查包括“通知获准、通道震动关闭”复现、原生/通知两种普通任务、真实五分钟前梯度及截止、冷进程恢复、关闭震动后的不请求、前台原生桥自检、横幅关闭和资源释放。核对系统震动服务完成记录及真实调用者，区分系统通知震动与应用原生震动。模拟器检查不能替代 OPPO 真机触觉与耗电测量。

生产包继续使用同证书非调试 Release 签名，支持覆盖升级；保留课表一键参考导入及限频更新提示。
