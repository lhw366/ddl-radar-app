## 课表必须覆盖的行为

1. 全新数据首次打开课表时课程为空。切换通用、北大时间模板只改变上课时间，
   不插入课程；普通模式无法导入管理员参考课表。
2. 同一图片连续导入两次，第二次只统计重复项，课表不增加课程。再次点击同一轮
   「确认导入」也不会重放上次结果。
3. 已有课表上导入默认使用「只补空缺」，保留已有课程与作息。同一天的相同、
   部分相交、完全包含的节次均检查冲突，且检查本批次课程之间的冲突。
4. 单周和双周课程可占用相同节次；每周课程与其中任意一门重叠时均视为冲突。
   手动添加、修改课程也使用同样规则。
5. 导入预览允许修改名称、教室、星期与节次。删除另一行时保留已编辑内容；
   取消或识别结果迟到时保持现有数据。
6. 只有明确选择「替换当前课表」才替换课程。导入作息随确认提交，默认补缺不会
   覆盖已有课表作息；4—20 节的自定义作息保存、恢复及提醒时间需一致。
7. 导入完成仅显示一条新增、重复与冲突汇总。界面操作提示的去重不能合并两个
   真正同时到点的提醒。

## 表单、账号与数据

- 在手机尺寸的真实 WebView 中打开长事项编辑页，滚动到保存按钮；验证键盘出现
  后仍可操作、顶部下拉和左侧返回手势可关闭、嵌套日期选择器只关闭最上层弹层。
- 日期选择器核对月份切换、相邻月份日期、整点与精确分钟、取消不提交和确认后
  保存事项。透明主题继续显示背景。
- 普通模式隐藏测试提醒、管理员课表、诊断和示例数据。现有安装迁移保留管理员
  能力，可关闭测试工具；新安装使用普通模式。
- 本机 ID 与昵称随 JSON 恢复包保存。恢复包是当前数据快照，导入会替换当前
  事项、课表与设置。卸载或清除数据前必须自行保存到应用以外；本版没有云账号、
  远程身份找回或跨设备自动同步。浏览器持久存储申请仅为尽力而为。
- APK 通过 Android Storage Access Framework 的 `ACTION_CREATE_DOCUMENT` 打开
  系统保存窗口，限定本地文件位置并由用户选择文件。恢复包包含当前事项、课表、
  昵称、设置与壁纸；只在文件写入并关闭成功后返回保存完成。取消或写入失败不能
  报告成功，重复点击不能同时打开两个保存窗口，不申请全部存储访问权限。
- 网页环境继续使用浏览器下载；「已发起下载」与 APK「恢复包已保存」区分显示。
  导出的 JSON 应重新导入，核对账号、课程与壁纸；也需验证旧版本 JSON 可恢复。
- 反馈仅由用户主动复制或打开 GitHub 草稿，不自动提交。核对载荷不附带事项、
  课表、账号 ID、图片或诊断。

## 提醒回归范围

本次原生改动包括提醒卡片交互、OCR、恢复包保存及插件注册。`AlarmScheduler`、
`AlarmService`、`AlarmReceiver`、`AlarmDelivery` 与 `www/js/nativenotify.js` 的排期
和到点派发实现保持基线；`app.js` 的 `planReminders` 和到点派发核心保持原样。
课表保存仍通过既有
`save()` 与 `Timetable.planFor()` 进入原生排期，需以普通课程提醒和普通事项梯度
回归确认集成。

顶部横幅与锁屏提醒卡片新增上滑收起及内容点击。点击通过显式 `ACTION_VIEW`
打开 `MainActivity`，URL 为 `ddlr://reminder/<提醒哈希>`；应用分别接收运行中的
`appUrlOpen` 和冷启动的 `getLaunchUrl`，定位当前事项或课程。找不到原对象时
应回到应用的安全默认页面，不修改课程或事项。

交互验收包括：真实上滑只移除触摸到的卡片；点击第一张或第二张仅关闭本卡片，
另一张保留；侧滑和多指取消不能误触打开；关闭按钮、手动保留与 5 秒自动关闭
继续有效。锁屏卡片只响应用户点击启动应用，安全锁屏仍由系统负责解锁。

保持手机静音时默认震动、声音关闭，尊重显式静默偏好。不申请电池白名单，不改变
用户电池设置。Android 36 回归需要覆盖正常梯度与截止、桌面横幅、静音触觉、取消、
重复入口和提醒结束后服务退出；原生测试使用一次性模拟器，不对用户手机执行。
