# 有限的临近提醒保护

此说明只描述通用代码与合成测试，不包含用户手机诊断。

## 为什么需要改变生命周期

精确闹钟回调可能提前或延后进入应用。先前提前回调会重排一次系统闹钟，服务随即结束；这样真正到点仍依赖一次新的后台入口。现在对三分钟内的已登记事项，原生短时服务可以先准备并等待到点，减少对这次新入口的依赖。

## 边界

- 正常任务梯度、自定义、课程、截止与显式测试共享持久化排期。仅当前有效登记、尚未派发且临近的事项能被保护。
- UI 保存通过 Capacitor 工作线程提交，原生准备有至多两秒的单次确认；不持有调度锁等待主线程，生命周期主线程不等待确认。
- 保护窗口约三分钟。等待期间仅安排一个主队列到点回调及一个终止回调，不周期扫描，不持有 CPU 唤醒锁，不用音频保活。已有系统闹钟继续负责设备睡眠时的唤醒。
- 到点回调重新核验登记与持久化事项，共用 AlarmDelivery 的去重、静音、勿扰和短时效果。派发路径记录为 protected_timer，不能伪装成新收到的系统闹钟入口。
- 编辑或取消会重新核对等待事项；转到远期、无可提醒内容或窗口到期后，服务在既有效果结束后退出。重复提前回调不延长窗口。
- 手动保留的横幅仍按用户设置保留服务，且不长期持有 CPU 锁。
- 没有新增预唤醒系统闹钟或并行备份闹钟。远期事项依赖系统唤醒；普通 APK 不能据此保证绕过所有 OEM 限制。实际续航与时效必须测量，不能宣称零功耗。

## 验证

NearReminderProtectionTest 使用真实页面保存与桥接，确认原生准备后按 Home，故意取消系统到点回调但保留有效登记。必须仍在后台完成正常事项，静音时仅请求触觉，且迟到的系统副本不能再次产生效果。其他用例检查改到远期立即释放保护、远期事项不常驻。

提前投递回归继续覆盖原生 PendingIntent、重排以及取消和旧参数。冻结宿主测试会在隔离模拟器中明确停止保护服务，独立验证系统闹钟兜底路径，避免强制冻结一个前台服务进程后误称为正常缓存场景。真实五分钟梯度和截止测试继续保留。
