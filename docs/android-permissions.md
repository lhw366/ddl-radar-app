# 签名、安装来源和后台提醒（v2.3.3）

APK 使用原项目证书签署非调试 Release 包，保留覆盖升级身份；CI 验签并拒绝 debuggable 包。签名不能把本地安装变成商店安装，也不能自动解除权限限制。

系统通知横幅和跨应用悬浮横幅是两条路径：系统横幅由手机的通知权限、通道及横幅开关控制；自定义悬浮横幅需要“显示在其他应用上层”。应用内下载提示仅显示下载状态，不能证明后台横幅可用。

未知来源权限受限时，可从应用信息页查看是否提供“允许受限设置”，阅读系统说明后自行决定；ColorOS 具体按钮以实际界面为准。应用不能代为同意或伪造安装来源。[Android 16 CDD](https://source.android.com/docs/compatibility/16/android-16-cdd#9_8_privacy)

用户提供的 v2.3.2 b82 诊断显示 `ringerMode=0`、`notificationVolume=0`、勿扰过滤值 `1`（允许全部），震动却以 `ringer_silent` 提前返回。这证明旧版应用在调用震动 API 前主动阻止了请求，不能据此认定 Android 已尝试震动并拒绝。

v2.3.3 的“系统静音时震动”偏好 `vibrateInSilent` 默认开启，可单独关闭。它仅在应用震动已开启时生效；应用全局“静默” `remindSilent` 或三种输出全关仍清除提醒排期。系统静音与应用全局关闭提醒是不同设置。

手机处于 `RINGER_MODE_SILENT` 且勿扰为 `INTERRUPTION_FILTER_ALL` 时，有限服务按偏好发起纯触觉 `USAGE_ALARM` 请求；此用途不创建音频、不修改音量，也不设置绕过策略的 flags。偏好关闭时记录 `blocked_preference`。手机非静音时，原生兼容震动仍使用 `USAGE_NOTIFICATION`；普通通知模式继续保留用户通道设置。

勿扰为 NONE 或 ALARMS 时抑制原生震动；静音下 PRIORITY 也抑制，不提升为 ALARM 用途。非静音下 PRIORITY 的通知触觉仍交给系统策略。应用不会修改静音、勿扰或系统音量。

响铃与触觉分开判断：`ReminderSound` 始终使用 `USAGE_NOTIFICATION`，仅应用响铃开启、手机为 NORMAL、通知音量大于零且勿扰为 ALL 时播放。系统静音时不会因为开启“系统静音时震动”而响铃。

通道共 14 个：保留 8 个 v4 与 4 个 v5，增加 2 个 v6 quiet 通道。系统静音时实际通知使用 quiet 通道，仅提供无声视觉提示，通道震动关闭；高重要性通道挂无声 PCM，普通通道无声音。触觉由有限服务单独负责，避免重复；正常模式的 v5 若被用户开启通道震动，选择通知通道这一处产生震动。返回应用后刷新实际通道状态。

`vibrateInSilent` 随每条正常梯度、截止、课程及 5/60 秒测试的 JSON 与 PendingIntent 保存；重启、更新恢复及周期续排继续沿用。调度规格为 `SCHED_VER=14`，旧记录缺省为开启；改变偏好会重新协调未来排期。

纯震动派发服务约 2.2 秒释放；响铃路径约 4 秒释放，不增加后台轮询、长期唤醒锁，不更改省电设置或申请电池白名单。

自检和诊断分别显示闹钟送达、震动派发状态及失败原因；前台原生 API 请求成功仍不能证明手机硬件已经震动。模拟器验收不能代替 OPPO 真机触感和后台横幅验收。
