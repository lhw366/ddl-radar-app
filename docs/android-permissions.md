# 签名、安装来源和后台提醒

APK 签名用于验证安装包与更新身份。v2.3.0 已用项目证书签名，但之前交付的是可调试构建；v2.3.1 起发布同一证书签署的非调试 Release 包，CI 使用 apksigner 验签并拒绝 debuggable 包。保留原证书以便覆盖升级。

签名不等于应用商店安装来源，也不能自行解锁悬浮窗。用户反馈的“已限制向此应用授予悬浮窗……已限制未知来源应用获取部分权限”，与 Android 16 的受限设置机制相符。系统将本地/下载文件安装与商店安装区别处理，并要求从应用信息页由用户确认。具体按钮取决于 ColorOS 的实际界面，应用不能自动同意或伪造商店安装来源。[Android 16 CDD](https://source.android.com/docs/compatibility/16/android-16-cdd#9_8_privacy)

在应用里点击“未知来源权限受限？打开应用信息”，查看右上角菜单中是否提供“允许受限设置”。阅读系统说明后自行决定，再返回悬浮窗授权。若系统没有提供该选项，重新签名没有自动解锁效果。应用默认保留系统通知路径，不强制要求悬浮窗。

v2.3.1 改用系统 NotificationChannel 的震动，8 种通道编码响铃、震动、横幅三个独立开关。通知已提交时不再同时调用直接震动，避免重复。系统通知权限被拒绝时，才在有限前台派发服务启动后尝试震动兜底，记录失败与设备能力；不把 API 请求成功描述成硬件已震动。

CI 的正常五分钟前梯度和截止提醒测试明确拒绝悬浮窗权限，检查实际系统通知和震动通道。独立用例在进程启动前拒绝通知权限，检查兜底服务的调用顺序和释放。现有横幅、周期续排、课表测试继续执行。模拟器不代替 OPPO 真机触觉；用户手机的完整诊断仍用于区分后台广播未到与震动被系统限制。

诊断增加公开签名指纹、可调试标记、安装来源、通知震动开关、后台受限状态、通知音量和震动强度。以上仅查询，不关闭省电模式、不申请电池白名单、不增加周期后台保活。
