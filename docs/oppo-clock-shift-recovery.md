# ColorOS 提前回调后的时钟补偿

build 108 的实机诊断显示，一个计划在 00:14 到点的普通提醒先被 ColorOS
提前触发；恢复路径随后改用 `setExactAndAllowWhileIdle`，但该提醒直到 00:17:36
才执行。同一份记录中，5 秒测试没有经过这条受限恢复路径，所以一直准确。

新的恢复逻辑仍只重排一次，但保持在使用 `setAlarmClock` 的可唤醒通道，并记录本次
系统提前量。替代闹钟的触发时刻会加上这段补偿和一个 1.5 秒安全余量，避免再次被
同一厂商偏差提前。补偿最多两分钟，第二次提前回调不会继续创建重试链。

等待期间不申请电池优化白名单、不常驻高耗电服务、不轮询，也不持有 CPU 唤醒锁。
原有的有限保护服务和系统闹钟都保留；恢复闹钟只是替换已经被消费掉的那一枚提前
回调令牌。若用户在两枚回调之间撤销精确闹钟权限，代码退回系统允许的
`setExactAndAllowWhileIdle` 通道并在诊断中明确标记 fallback。

原生测试会直接消费一个未来提醒令牌，确认恢复模式为
`clock_shift_compensation`、替代触发时刻晚于原截止、等待时不持有 CPU 锁，
并继续验证原本的重复去重、取消、编辑和 5 秒测试链路。
